## 1. 大規模ハードウェア設計における課題

### フラット設計（単一巨大モジュール）の限界
すべての回路を1つの `Module` 内にフラットに記述すると：
- 信号線名が衝突し、可読性と保守性が著しく低下する。
- 既存の回路ブロック（加算器やカウンタなど）の再利用が困難になる。
- 部品ごとの単体テスト（Unit Test）が不可能になり、バグの特定が困難になる。

### 構造化設計 (Structured Hierarchical Design)
回路を明確な機能境界を持つ独立した「サブモジュール」に分割し、最上位（トップモジュール）でそれらを結線する手法。

<p align="center"><img src="figures/lecture05_hierarchy_concept.svg" width="660"></p>

<!-- Note:
構造化設計の必要性です。
数百万ゲートにも及ぶ現代のSoCやCPUは、決して1つのファイルにベタ書きされているわけではありません。
機能ごとにモジュールに分割され、綺麗な階層構造を形成しています。
モジュールごとに独立して設計・テストできることが、信頼性の高いハードウェア開発の絶対条件です。

## 2. Chiselにおけるモジュール階層とインスタンス化

### モジュールの定義
Chiselでは、回路ブロックはすべて `Module` を継承したクラスとして定義します。

```scala
class SubCounter(val maxVal: Int) extends Module {
  val io = IO(new Bundle {
    val en   = Input(Bool())
    val out  = Output(UInt(4.W))
    val cout = Output(Bool())
  })
  // 内部回路の実装
}
```

### サブモジュールのインスタンス化 (`Module(...)`)
親モジュール内で子モジュールを実体化（配置）するには、**`Module(new ...)`** を使用します。

```scala
class TopModule extends Module {
  val io = IO(new Bundle { /* 外部ポート */ })

  // 子モジュールを実体化
  val sub1 = Module(new SubCounter(10))
  val sub2 = Module(new SubCounter(6))

  // ポート間の配線
  sub1.io.en := io.en
  sub2.io.en := sub1.io.cout
}
```

<!-- Note:
Chiselにおけるモジュール定義とインスタンス化の基本構文です。
class SubCounter extends Module で定義された部品は、親モジュールの中で val u = Module(new SubCounter) と書くことで実体化されます。
親と子の通信は、互いの io ポートを := で接続することで配線されます。
-->

## 3. 60進カウンタ (Modulo-60 Counter) の必要性

### 時計システム（Timekeeping System）の基本構造
- 1秒パルス（1Hz）を受けて、**秒 ($0 \sim 59$)** を計数する。
- 秒が59から0に戻る瞬間に桁上げパルスを発生させ、**分 ($0 \sim 59$)** を進める。
- 分が59から0に戻る瞬間に桁上げを発生させ、**時 ($0 \sim 23$)** を進める。

### 60進数をどう構成するか？
直接0〜59を数える6ビットカウンタを作ることも可能ですが、7セグメント表示器等に出力する場合、**「1の位（0〜9: 10進数）」と「10の位（0〜5: 6進数）」に最初から分離（BCD形式）して構造化**する方が圧倒的に扱いやすくなります。

$$60 = 10 \times 6$$

<!-- Note:
時計回路の設計動機です。
60進カウンタを単一の0〜59のバイナリカウンタとして作ってしまうと、LEDディスプレイに表示する際に「59を10で割って商の5と余りの9を求める」という重い除算器が後段に必要になってしまいます。
しかし、最初から「1の位の10進カウンタ」と「10の位の6進カウンタ」を階層的に組み合わせれば、割り算回路は一切不要になります。
-->

## 4. 【最重要工学原則】非同期リップルクロックの絶対禁止

下位カウンタの桁上げ出力を、上位カウンタのクロック入力に繋ぐ回路（リップルクロック）。

<p align="center">
  <img src="figures/lecture06_bad_ripple.svg" width="640">
</p>

<div class="box">
<b>なぜ非同期リップルクロックはダメなのか？</b><br>
1. <b>クロックスキューの累積</b>: 10進カウンタのフリップフロップ遅延が、6進カウンタのクロック遅延となり、段数が増えるほどタイミングがズレる。<br>
2. <b>グリッチによる誤カウント</b>: 桁上げ信号に生じたヒゲ（グリッチ）がクロックパルスと誤認され、余分にカウントアップする。<br>
3. <b>静的タイミング解析 (STA) の破綻</b>: 異なるクロックドメインが混在し、自動配置配線ツールでタイミング収束ができなくなる。
</div>

<!-- Note:
本講義で最も強く強調したいスライドです。
初心者が回路図を描くとき、10進カウンタのcoutを6進カウンタのクロック端子に繋いでしまいがちです。
これは「リップルクロック（非同期クロック）」と呼ばれ、現代の大規模集積回路（ASICやFPGA）では厳禁とされています。
クロックに遅延が生じ、桁上げ信号のわずかなグリッチで上位桁が2回進んでしまうといった怪現象が多発するためです。
Chiselでも、暗黙の単一クロックを使うことでこの悪習を構造的に排除しています。
-->

## 5. 正しい設計原則: 同期イネーブル伝播 (Synchronous Enable Propagation)

すべてのカウンタに**同一のシステムクロック（System Clock）**を供給し、下位の桁上げを**イネーブル信号 (`en`)** として上位へ伝播させる。

<p align="center">
  <img src="figures/lecture06_good_sync.svg" width="680">
</p>

- **単一クロック**: すべてのフリップフロップが同一のクロック立ち上がりで一斉に動作。
- **イネーブル制御**: 6進カウンタは、10進カウンタが「9」になった瞬間（桁上げ有効）の次のクロックエッジでのみ値を更新。

<!-- Note:
同期設計の黄金律です。
回路全体に供給されるクロックはただ1つです。
10進カウンタも6進カウンタも、全く同じクロックエッジを見ています。
6進カウンタが進むべきタイミングは、「10進カウンタからの桁上げイネーブル信号」によって制御します。
これにより、クロックスキューの累積もグリッチの誤カウントも完全にゼロになります。
-->

## 6. 10進カウンタと6進カウンタの協調動作

### モジュロNカウンタ (`ModuloNCounter`) の再利用
第3回で設計した汎用カウンタをそのままサブモジュールとして活用：
- **1の位**: `ModuloNCounter(n = 10, width = 4)` $\implies 0 \to 1 \to \cdots \to 9 \to 0$
- **10の位**: `ModuloNCounter(n = 6, width = 3)` $\implies 0 \to 1 \to \cdots \to 5 \to 0$

### 桁上げ発生の条件
10進カウンタの現在値が $9$ で、かつ外部イネーブル `en` が `true.B` のとき：

$$\mathbf{rollover_{10}} = (\mathbf{count_{10}} == 9) \ \land \ \mathbf{en}$$

- この `rollover10` パルスを、そのまま6進カウンタの `io.en` 入力に配線する！

<!-- Note:
10進と6進の連携ロジックです。
第3回で作った ModuloNCounter をそのまま使います。
10進カウンタが 9 に達したとき、rollover 信号が 1 になります。
この信号を6進カウンタの en 端子に入れておけば、次のクロックの瞬間に「10進カウンタが0に戻る」のと「6進カウンタが1増える」ことが完全に同一クロックエッジで同時に発生します。
-->

## 7. 桁上げ同期パルスのタイミング検証

60進カウンタの遷移タイミング波形：

```
Clock:     _/~~\__/~~\__/~~\__/~~\__/~~\__/~~\__/~~\_
en:        ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
secUnits:    [ 8 ]  │ [ 9 ]  │ [ 0 ]  │ [ 1 ]  │
rollover10: ________/‾‾‾‾‾‾‾‾\________________________ (9の時だけHigh)
secTens:     [ 0 ]          │ [ 1 ]          │
```

- クロック立ち上がり直前の「セットアップ時間」において、`rollover10` が安定している。
- 次の立ち上がりエッジで、**`secUnits` が 9 $\to$ 0 になると同時に、`secTens` が 0 $\to$ 1 に遷移**する。
- 状態遷移のズレ（非同期スキュー）は原理的に **0 ピコ秒**。

<!-- Note:
タイミングチャートによる検証です。
波形を見ると分かる通り、secUnitsが9の期間中、rollover10がHighになります。
そして次のクロックの立ち上がりエッジで、secUnitsは0になり、secTensは1になります。
2つのレジスタが寸分の狂いもなく同時に値を更新します。これが同期回路の美しさです。
-->

## 9. `Counter60` のChisel完全実装

```scala
class Counter60 extends Module {
  val io = IO(new Bundle {
    val en       = Input(Bool())
    val clear    = Input(Bool())
    val secUnits = Output(UInt(4.W)) // 0〜9
    val secTens  = Output(UInt(3.W)) // 0〜5
    val cout     = Output(Bool())    // 59でアサート
  })

  // サブモジュールのインスタンス化
  val mod10 = Module(new ModuloNCounter(n = 10, width = 4))
  val mod6  = Module(new ModuloNCounter(n = 6,  width = 3))

  // 10進カウンタの配線
  mod10.io.en    := io.en
  mod10.io.clear := io.clear
  io.secUnits    := mod10.io.count

  // 6進カウンタの配線（同期イネーブル伝播）
  mod6.io.en    := mod10.io.rollover && io.en
  mod6.io.clear := io.clear
  io.secTens    := mod6.io.count

  // 60進全体の桁上げ出力 (59の計数完了時)
  io.cout := (io.secTens === 5.U) && (io.secUnits === 9.U) && io.en
}
```

<!-- Note:
Counter60 の完全なコードです。
非常にすっきりと書けていることが分かります。
mod6.io.en := mod10.io.rollover && io.en の1行が、本講義の核心である同期イネーブル接続です。
io.cout は 59 のときに有効化されます。
-->

## 10. `Counter60` のシミュレーション波形検証

### 58秒 $\to$ 59秒 $\to$ 00秒 の境界遷移テスト

```
Time:     ... 57      58      59      00      01 ...
en:       ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
secTens:      5       5       5       0       0
secUnits:     7       8       9       0       1
cout:     ___________________/‾‾‾‾‾‾‾‾\_____________
```

- 59秒のサイクルでのみ `cout` が綺麗に 1 クロック幅で立ち上がる。
- 次のサイクルで `secTens` と `secUnits` が同時に `0` にクリアされる。
- グリッチのないクリーンなパルスが生成される。

<!-- Note:
シミュレーション波形の確認です。
59秒になった瞬間、coutが立ち上がります。
そして次のクロックで 00秒 に戻り、coutも立ち下がります。
このクリーンな1クロック幅のパルスがあるからこそ、次段の「分カウンタ」を正しく1つだけ進めることができるのです。

## 13. モジュール分割の設計原則

良いハードウェア構造化のための3大原則：

1. **高凝集・低結合 (High Cohesion, Low Coupling)**:
   - 強く関連する論理（秒の1の位と10の位）を1つのモジュールにまとめ、外部との配線本数を最小化する。
2. **入出力方向の明確化**:
   - `Bundle` 内で `Input` と `Output` を厳格に宣言し、未接続ピンを残さない。
3. **同期境界の一貫性**:
   - 回路全体でクロックを共有し、制御信号（イネーブルやクリア）で動作タイミングを調停する。

<!-- Note:
ハードウェアアーキテクチャの心得です。
ソフトウェアの設計原則である高凝集・低結合は、ハードウェアでも全く同じです。
ピン数が多いと配線が混雑してチップ面積を圧迫します。
すべてのモジュールが同じクロックを共有し、イネーブル信号で会話することが最も美しい設計です。
-->

## 16. 第5回 まとめ & 次回予告

### 本日の重要ポイント
1. 階層化設計により、大規模回路の可読性・再利用性・保守性を飛躍的に高める。
2. サブモジュールは `Module(new SubModule)` で実体化し、`io` ポートを配線する。
