## 1. デジタルハードウェアにおける記憶素子の階層

ハードウェアの記憶素子は、「アクセス速度」と「回路面積（ビット単価）」のトレードオフによって階層化されています。

<p align="center"><img src="figures/lecture08_memory_hierarchy.svg" width="680"></p>

- **フリップフロップ群 (`RegInit`)**: 全ビットに独立配線。面積は巨大だが1サイクルで自在に並列アクセス可能。
- **メモリ構造 (`Mem`)**: アドレスデコーダを共有し、指定した1ワードのみを読み書きする高密度構造。

<!-- Note:
記憶素子のピラミッド構造です。
全部のメモリをRegで作れば最速ですが、1ビットあたり十数個のトランジスタを消費するためチップ面積が爆発します。
一方、SRAMやメモリブロックはアドレスデコーダを共通化してビットセルを格子状に並べるため、面積を劇的に小さくできます。
その代わり、1回にアクセスできるアドレスが制限されます。
-->

## 2. 非同期読み出し vs 同期読み出し

メモリの読み出し方式には、工学的に極めて重要な2つの方式があります。

<p align="center"><img src="figures/lecture08_async_vs_sync_read.svg" width="680"></p>

- **非同期読み出し (`Mem`)**: アドレスを与えると**クロックを待たずに同一サイクル内で即座に出力**（0サイクル遅延）。CPUのレジスタファイル等に不可欠。
- **同期読み出し (`SyncReadMem`)**: アドレス入力後、**次のクロック立ち上がりエッジ**でデータ確定（1サイクル遅延）。FPGAの専用ブロックRAM（BRAM）や大容量キャッシュ向け。

<!-- Note:
本日の核心テーマである「非同期読み出し vs 同期読み出し」です。
非同期読み出しは、アドレスを与えた瞬間にデータが出てきます。つまり「巨大なマルチプレクサ」として振る舞います。
一方、同期読み出しはアドレスを与えてクロックが1回カチッと鳴って初めてデータが出てきます。
FPGAの大容量BRAMは同期読み出ししかできませんが、CPUのレジスタファイルのように「同じサイクルで読んだ値を使って即座にALUで計算したい」場合は、非同期読み出しメモリ（分散RAMやFFアレイ）が不可欠になります。
-->

## 3. Chiselにおける `Mem`: 非同期読み出しメモリ

Chiselで非同期読み出しメモリを生成するには、`Mem` プリミティブを使用します。

```scala
// 8ワード、各ワード8ビット幅のメモリ配列を生成
val mem = Mem(8, UInt(8.W))

// 1. 同期書き込み (クロック立ち上がりで書き込み)
when(io.wen) {
  mem(io.waddr) := io.wdata
}

// 2. 非同期読み出し (アドレス指定で即座にデータが出力)
io.rdata := mem(io.raddr)
```

- **書き込み**: 常にクロックに同期（`when(wen)` で指定）。
- **読み出し**: 純粋な組合せ論理として動作（クロック遅延なし）。

<!-- Note:
Chiselでの Mem の書き方です。
非常に直感的です。
mem(io.waddr) := io.wdata を when(io.wen) の中に書くことで、書き込みイネーブル付きの同期書き込みになります。
そして io.rdata := mem(io.raddr) と書くだけで、クロックを待たずに即座にデータが読み出される非同期ポートが生成されます。
-->

## 4. マルチポート・レジスタファイル (Register File)

現代のプロセッサ（RISC-V等）では、1命令で2つのレジスタから値を読み出し、1つのレジスタへ書き戻すため、**「2読み出しポート・1書き込みポート (2R1W)」**の構成が標準です。

<p align="center"><img src="figures/lecture08_regfile_block.svg" width="640"></p>

- 2つの読み出しポートは互いに完全に独立しており、同一サイクルに異なる2つのアドレスを同時に読み出せる。

<!-- Note:
2R1Wレジスタファイルの構造です。
例えば加算命令 `add r3, r1, r2` を実行するとき、プロセッサは1サイクルの間に r1 と r2 の両方を同時に読み出し、ALUに渡す必要があります。
したがって、読み出しポートが独立して2本必要になります。
Chiselではこれを驚くほどシンプルにモデル化できます。
-->

---

## 5. 2R1W レジスタファイルの実装コード

```scala
class RegisterFile8x8 extends Module {
  val io = IO(new Bundle {
    // 読み出しポート1 & 2 (非同期)
    val raddr1 = Input(UInt(3.W))
    val rdata1 = Output(UInt(8.W))
    val raddr2 = Input(UInt(3.W))
    val rdata2 = Output(UInt(8.W))

    // 書き込みポート (同期)
    val wen    = Input(Bool())
    val waddr  = Input(UInt(3.W))
    val wdata  = Input(UInt(8.W))
  })

  val mem = Mem(8, UInt(8.W))

  // 同期書き込み
  when(io.wen) {
    mem(io.waddr) := io.wdata
  }

  // 2つの独立した非同期読み出しポート
  io.rdata1 := mem(io.raddr1)
  io.rdata2 := mem(io.raddr2)
}
```

<!-- Note:
本日の基本問題の完全なコードです。
同じ mem インスタンスに対して、異なるアドレス raddr1 と raddr2 でインデックス参照するだけで、ハードウェアとして2つの独立した読み出しデコード回路が並列に合成されます。
これがChiselの高水準な記述力です。
-->

## 6. 【最重要工学的課題】Read-After-Write (RAW) 競合

### RAW競合とは
「**同一クロックサイクル**において、**同一アドレス**に対して書き込みと読み出しが同時に発生した場合、読み出しポートには何が出力されるべきか？」

$$waddr == raddr1 \quad \text{かつ} \quad wen == 1$$

### 物理メモリの未定義動作
- 書き込みデータがメモリセルに定着するのは「次のクロックの立ち上がりエッジ」。
- 一方、非同期読み出しは「現在のサイクル中」にセルを覗き見る。
- $\implies$ **古い値（更新前のデータ）が読まれるか、過渡的な不定値 (X) が読まれてしまう！**

<!-- Note:
ハードウェア設計の超重要トピック「RAW競合」です。
命令パイプラインで「r1に10を書き込む」命令の直後に「r1の値を読む」命令が来たとき、メモリセルへの書き込みが完了する前に読み出しが行われると、古いデータが読まれて大惨事になります。
これに対処するのが、プロセッサの高速化の要である「バイパス（フォワーディング）回路」です。
-->

---

## 7. RAWフォワーディング（バイパス）回路の原理

メモリセルへの書き込みを待たずに、**書き込みデータを直接読み出しポートへショートカット（迂回）**させる。

<p align="center"><img src="figures/lecture08_raw_forwarding.svg" width="680"></p>

- **バイパス判定条件**:
  $$bypass = wen \land (waddr == raddr)$$
- $bypass$ が真ならば、メモリセルを通さず `wdata` を即座に出力！

<!-- Note:
フォワーディング回路のブロック図です。
発想は極めてシンプルかつ強烈です。
「同じアドレスに今まさに書こうとしているなら、メモリセルを通さずに、入力ピンにある最新の wdata をそのまま読み出しピンにバイパス（直結）してしまえば良い」というアプローチです。
これにより、同一サイクル内での最新データの可視性が100%保証されます。
-->

## 8. RAWバイパス回路付きレジスタファイルの実装

```scala
class BypassedRegisterFile extends Module {
  val io = IO(new Bundle {
    val raddr1 = Input(UInt(3.W)); val rdata1 = Output(UInt(8.W))
    val raddr2 = Input(UInt(3.W)); val rdata2 = Output(UInt(8.W))
    val wen    = Input(Bool());    val waddr  = Input(UInt(3.W))
    val wdata  = Input(UInt(8.W))
  })

  val rf = Module(new RegisterFile8x8)
  rf.io.raddr1 := io.raddr1; rf.io.raddr2 := io.raddr2
  rf.io.wen    := io.wen;    rf.io.waddr  := io.waddr; rf.io.wdata := io.wdata

  // RAW競合の検出
  val bypass1 = io.wen && (io.waddr === io.raddr1)
  val bypass2 = io.wen && (io.waddr === io.raddr2)

  // MUXによるフォワーディング
  io.rdata1 := Mux(bypass1, io.wdata, rf.io.rdata1)
  io.rdata2 := Mux(bypass2, io.wdata, rf.io.rdata2)
}
```

<!-- Note:
発展問題の模範解答コードです。
先ほど作った RegisterFile8x8 をサブモジュールとして内包し、その外側に bypass 判定と比較器、そして Mux を配置しています。
これぞまさに第5回で学んだ構造化設計の真骨頂です。

## 9. タイミング波形によるRAWフォワーディングの検証

アドレス `2` に対して、書き込み (`0x42`) と読み出しが同一サイクルで衝突した場合：

```
CLK      : ──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐
             └──┘  └──┘  └──┘  └──┘  └──┘  └──
waddr    : ──X         2        X─────────────
wdata    : ──X        0x42      X─────────────
wen      : ──|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾|─────────────
raddr1   : ──X         2        X─────────────
bypass1  : ──|‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾|───────────── (即座に検出)
rdata1   : ──X        0x42      X───────────── (クロックエッジを待たずに0x42が出現！)
```

- クロックエッジの到着を待たずに、同じサイクル内で即座に `0x42` が出力される。
- これにより、後続のALUステージがストール（待ち時間）なしで演算を継続できる。

<!-- Note:
タイミング波形です。
クロックエッジが来る前のサイクルの中で、すでに rdata1 に最新データ 0x42 が現れていることが確認できます。
もしバイパス回路がないと、このサイクルでは古いデータ（あるいは不定値）が出てしまい、CPUパイプラインを1サイクル停止（ストール）させなければならなくなります。
このわずかな回路が、プロセッサのIPC（1サイクルあたり実行命令数）を飛躍的に向上させます。
-->

## 10. `SyncReadMem`（同期読み出し）との使い分け指針

実務において `Mem` と `SyncReadMem` をどう選択すべきか？

| 特性 | `Mem` (非同期読み出し) | `SyncReadMem` (同期読み出し) |
| :--- | :--- | :--- |
| **読み出しレイテンシ** | **0サイクル (組合せ回路)** | **1サイクル (同期レジスタ)** |
| **物理ハードウェア** | 分散RAM (LUT-RAM) / FF配列 | **専用ブロックRAM (BRAM)** |
| **集積規模** | 小容量向け (数KB以下) | **大容量向け (数十KB〜数MB)** |
| **最大動作周波数** | 低〜中 (組合せ遅延大) | **極めて高い (専用高速マクロ)** |
| **代表的な用途** | **CPUレジスタファイル**, 小規模FIFO | **L1/L2キャッシュ**, パケットバッファ |

<!-- Note:
実務設計におけるメモリ選定の極意です。
初心者は全部非同期の Mem で作りたがりますが、FPGAやASICでは大容量のメモリをLUTやFFで作るとチップ面積をあっという間に使い果たしてしまいます。
したがって、小規模なレジスタファイルは Mem、大規模なデータバッファは SyncReadMem、というように目的と容量に応じて厳格に使い分けるのがプロの技法です。
-->
